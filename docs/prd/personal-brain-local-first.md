# PRD: 个人大脑本地先行版（Personal Brain Local-First）

> 本轮状态：按用户最新决定直接进入实施计划。首版办公接入仅飞书和腾讯会议，连接/授权/读取范围/同步/断开统一放在主侧栏「连接」页；WPS 与国内 Runtime 后置。规划前不再要求采样、PoC 或模型联调，未验证事项纳入实施验收，不代表已通过。最新范围以 R9、§9、§13.9 为准，旧评审仅保留历史溯源。

## 1. 背景

Company Brain POC TRD（见 sources）定义了一条「工作轨迹 → Work Unit → 团队知识 → 混合检索问答 → 反馈更新」的知识编译管道，但其主形态是云端 Team Brain + 多人协作。本 PRD 将该管道的**本地可裁剪子集**落到 screenpipe（zh-local 分支）上，做成单机、个人维度的先行版，用于验证：真实工作轨迹能否在无人值守下沉淀为可检索、带证据、可维护的个人知识。

现状基础（已存在，不需要新建）：

- 采集与全文检索：OCR / Accessibility / 音频采集 + SQLite FTS5（`/search`）。
- 工作解释的两层雏形：确定性 activity ledger（任务区间 + 证据表 + 级联删除）与 LLM 生成的 activity history（叙事 timeline）。
- 事实型记忆：`memories` 表 + REST/MCP CRUD + 外部文件同步（CLAUDE.md / AGENTS.md / Obsidian）。
- 桌面后台 AI 任务的复用基础：`run_background_pi` 依赖 Tauri 应用状态；activity history 已有证据包预注入与校验回修流程，尚不等于可独立运行的 Local Brain worker。
- AI 接入：AI Preset（OpenAI-compatible / Ollama / 自定义端点），local-only 构建已移除账号流与云端 provider。

关键产品决策（已确认）：

1. **模型接入保留现有 AI Preset 形态**，不强制本地模型；用户自行选择模型服务（本地或云端 API 均可）。
2. 原始记录与派生知识以本地存储为真源；模型调用所需上下文按用户已有 Preset 配置发送，具体出口见 R6。
3. 记忆是检索的一路来源；首版沿用本地 memories，Provider 化与外部只读接入后置，本项目不负责跨设备一致性。
4. 知识沉淀**个人维度**：无团队、无 ACL，审核为个人自审。
5. 飞书和腾讯会议通过现有「连接」入口接入，只读取得授权范围内的资料；平台原件仍以平台为真源，本地只管理获准导入的证据副本和派生知识。第三方办公登录不重新引入 Screenpipe 云账号体系。

## 2. 目标

- 首版（MVP）打通：工作轨迹 → Work Unit → SOP / Decision Rule / Exception Playbook → 自审发布 → 本地 FTS 检索 → 带引用问答 → 纠错与修订。
- 证明至少一份真实 SOP 能被核验、修订，并在来源变化或删除后正确停止使用；删除与反馈属于首版。
- 保持现有 memories、时间浏览与搜索调用方兼容；后续通过实测决定是否引入向量、多源融合和外部 MemoryProvider。
- 延续已完成的本地化裁剪，新增能力不重新引入 Screenpipe 云账号、团队或云搜索依赖；飞书/腾讯会议的第三方授权仅服务显式启用的只读连接。
- 国内办公接入纳入首版：飞书覆盖业务消息与需求/调研文档，腾讯会议覆盖会议转写与纪要证据，统一在「连接」中管理（R9）；通用 `/answer` 与 MCP 仍在首版，国内 Runtime 的具名适配、消费联调与执行能力评估后置（R10）。

## 3. 非目标

- 不做原始采集库上传/同步、团队/组织协作、ACL、多用户、ConsentPolicy、计费；模型上下文与显式文件出口按 R6 管理。
- 不做 Skill 自动执行与高风险操作（发消息、改数据库、提审批）；Checklist 执行视图、Case 发布、Skill 编译属后续阶段。
- 不强制本地模型，不新增模型推理基础设施（DGX Spark / Qwen 常驻服务不在范围内）。
- 不做 Methodology（TRD 中的 P3 类型）。
- 不改动采集 / 编码 / DB 写入热路径；知识管道全部为离线批处理。
- 不替换现有 AI 接入形态（AI Preset 即唯一模型入口）。
- 首版不依赖向量召回、外部记忆服务、远程记忆写入或独立于桌面应用的无人值守服务；它们不进入首版验收。
- WPS 接入、全账号/全租户历史同步、双向办公写入、自动发消息/审批、会议创建修改及多 Runtime 调度均后置；首版允许显式选择的飞书资料与腾讯会议转写只读导入，不要求资料此刻必须显示在屏幕上，不扩展为通用连接器平台。
- 国内 Runtime 的新增兼容、安装/登录、具名 MCP 消费联调和 ACP 执行能力评估不属于首版；使用已有 Pi 及指定模型验收不等于增加国内 Runtime 适配。

## 4. 用户与场景

用户：主要从事开发工作的单人使用者（本机使用，无协作方）。真实沉淀范围包括需求分析、调研、业务沟通及其决策和异常处理；首版类型仍为 SOP / Decision Rule / Exception Playbook，不因此新增需求文档生成器或通用调研代理。

首批样本以“业务沟通 → 需求澄清 → 调研比较 → 记录决策依据”为组织主线，允许只出现其中一段，不虚构完整流程。验收时从真实样本中选定至少一个重复流程（≥3 会话），不能把不同项目的需求分析、调研和会议强拼成同一 SOP。优先验证“当时为什么这样决定”“类似需求应先确认哪些条件”“这个例外怎么处理”等问题；具体项目与会话在 §8 语料冻结时记录。

- **场景 A（后台沉淀）**：正常工作 → 定时/手动触发抽取 → 生成 Work Unit → 聚合编译知识候选 → 用户在审核台自审（编辑/发布/驳回/废止）。
- **场景 B（检索问答）**：问「遇到 X 异常怎么处理」「上周为什么延期」→ 本地 FTS 命中当前可用知识与记录 → 返回逐项引用、带版本的回答；不把推断当事实，无证据时拒答。
- **场景 C（记忆外接，后续）**：显式配置外部记忆引擎 → 只读检索并标注来源；失败时返回部分结果和可见诊断，不伪装为零命中。
- **场景 D（删除）**：删除屏幕、音频、UI 事件或本地记忆 → 立即禁止受影响内容用于新问答 → 清除系统管理的派生内容与副本；完成范围与失败项可见（R6）。
- **场景 E（纠错）**：指出回答中的具体错误 → 关联回答、知识版本和来源 → 暂停有问题的版本 → 修订、自审并发布替代版本（R7）。
- **场景 F（恢复）**：退出应用、休眠或模型离线 → 显示暂停/积压 → 恢复后补处理；期间已删来源不会被旧任务重新写回（R8）。
- **场景 G（办公连接）**：在「连接」中授权飞书或腾讯会议 → 指定文档、会话/时间范围或会议 → 导入内容 → 结合实际工作轨迹编译 Work Unit 与 SOP。展示完整/部分内容与来源时间；导入资料可作为检索材料，但没有活动证据时不声称用户已阅读、参会或执行其中操作。
- **场景 H（通用 MCP）**：兼容客户端或协议测试客户端通过 MCP 提问 → 得到 Local Brain 的回答、知识版本和来源 → 修订/删除后再次显式调用工具，返回当前状态；第三方客户端已保存的旧会话属于 R6 声明的外部副本。首版不指定国内 Runtime 作为验收消费端。
- **场景 I（首次启用）**：保全迁移现有 activity history 与 coverage → 默认只对启用后就绪区间进行 AI 抽取 → 用户单独启动近 7 天历史试跑。首次启用不自动重算全部历史，回填范围、进度和暂停/取消可见。
- **失败处理**：模型超时可重试一次；结构化输出非法可回修一次，单任务总模型调用不超过三次，之后进入待处理状态。无有效来源、已删除来源和超预算任务不盲目重试。

## 5. 需求

### R1 工作轨迹与 Work Unit

- 新增 `work_unit.v1`：task / inputs / actions / decisions（条件→动作）/ exceptions / outputs / result / evidence_refs / confidence。事实性字段必须关联支持它的证据；推断显式标注，无证据的 decisions / result 允许为空，不把“打开部署页面”推断为“部署成功”。
- 以 activity ledger 的 `final` 区间自动锚定；输入就绪指上游已处理该窗口当时可用的证据，不无限等待缺失音频。`provisional` 区间不编译知识，迟到证据作为输入修订处理；尊重 `user_locked`，显式工作会话后置。
- 来源引用区分 frame、ui_event、audio、本地 memory 及办公平台资料，记录稳定来源标识、来源修订、发生时间与原文节选。ledger 的 interval/evidence 行会重建，不得充当唯一永久标识；activity history 是派生叙事，不能替代原始证据。
- 同一逻辑任务、输入证据修订、抽取器/prompt/schema 版本的执行结果唯一；输入指纹变化必须允许生成新修订，不能被旧幂等结果吞掉。
- 区间重新归并、迟到转写或用户改分类后，受影响 Work Unit 标为过期并重新抽取；其知识版本暂停用于问答，复核后恢复或生成候选修订，不自动发布。删除走 R6，不按一般更新保留旧正文。
- Schema、引用存在性、引用属于本次证据包以及字段与证据的支持关系分别校验。抽取结果提交前再次确认来源修订与删除状态；失败回修与预算遵守 R8。
- activity history 迁到同库 SQLite，迁移保留条目与 coverage。任一时刻只有一个有效写入方；迁移失败可恢复，回退读取不得恢复已删除内容；具体迁移、加密边界与回退步骤由 TRD 定稿。
- 数据迁移与 AI 历史回填分别管理：迁移保全全部现存合法条目，遵守 R6 删除记录；不因默认只抽取新增数据而裁掉历史，也不在迁移时重新调用模型解释全部旧记录。历史回填沿用 R8 的显式范围与恢复规则。

验收标准：

- **AC-R1-01**：冻结的一天真实数据中，≥80% 的就绪 final 区间产出合法 Work Unit；分母与排除项事先记录，事实正确性另按 §8 评测。
- **AC-R1-02**：重复执行、崩溃重启不产生重复有效修订；迟到转写、区间重建和人工改分类均使旧输入失效并可重算。
- **AC-R1-03**：frame/audio/ui_event 或办公导入来源在抽取中被删除，结果不得提交；删除后不得留下含该来源信息的派生正文。
- **AC-R1-04**：迁移后现有条目/coverage 按删除记录核对一致；首次启用不为全量旧数据创建 AI 重算任务，历史试跑与新增任务有可区分的范围和进度。

### R2 个人知识编译与自审

- 第一版仅三种类型：SOP、Decision Rule、Exception Playbook；知识必带稳定 id、结构化 content、适用条件、Work Unit 修订与证据引用、status、version、confidence、review_after、supersedes。
- 共同步骤、适用条件、异常分支各自关联来源；相似不等于同一流程，不同条件下的操作不得拼成无条件 SOP。SOP 归纳需跨会话证据；决策规则/异常手册可从单次观察起草，但需标明单次观察与适用条件，不泛化为稳定规律。证据不足时保留 Work Unit，不强制生成知识。
- 知识版本状态：`candidate → published / rejected`；发布替代版本时旧版本转为 `superseded`；用户可将已发布版本 `deprecated`。`extracted` 只描述抽取完成，不再作为知识发布状态。
- 草稿允许编辑并记录修订；已发布正文不覆盖，修改产生新候选版本。v2 审核期间 v1 在仍然有效时继续可用，v2 发布与 v1 替换同时生效；同一知识至多一个当前发布版本。
- 可用性独立于版本状态：来源过期、确认有误或复核到期时暂停普通问答。首版 `review_after` 默认发布/确认仍适用后 30 天，可按条目调整；到期提醒并暂停，用户确认仍适用留下复核记录，修改正文则产生新版本。
- 相似候选不自动合并；记录驳回原因及输入修订，相同输入不得重复打扰。只有新增实质证据或用户主动重试才可重新提案，并展示与上次差异。
- 审核台支持来源对照、编辑、发布、驳回、废止、版本比较与待复核列表；新增事实性内容需有支持来源。每次发布检查来源有效性和声明支持，不允许仅凭模型 confidence 发布。
- 候选与到期复核集中展示，按每天约 5 分钟集中审核设计；不逐条弹窗催审。候选数量与排序结合实际审核耗时调整，超出可处理量时保留可见积压，不自动发布、批量确认或悄悄丢弃候选。用户主动审核仍可随时进行，具体入口和提醒方式由界面设计定稿。
- 候选、驳回、被替代、废止和暂停版本不作为普通问答知识；历史查看适用 R6，用户删除优先于历史保留。

验收标准：

- **AC-R2-01**：同一流程 ≥3 个独立工作会话编译出一份含共同步骤、适用条件和异常分支且各有来源的 SOP 草稿；人工确认可用性。
- **AC-R2-02**：演示候选驳回不重复生成、v1→v2 修订替换、废止与到期复核；普通问答只使用当前可用版本。
- **AC-R2-03**：编辑引入无支持事实、来源归档后不足以核验或发布瞬间来源被删除时，阻止发布并展示原因。

### R3 本地检索与兼容性

- 旧 `/search` 默认 All 行为、时间排序（含升序）、offset/limit/total 与响应形态保持兼容，不隐式加入知识、外部网络请求或相关性排序。
- 首版 `/answer` 使用独立的本地检索编排：原始记录与已导入办公证据的本地 FTS + 本地 memories + 当前可用知识 FTS；按相关性取有限 top-k，不借用旧接口的精确 total 语义。向量、semantic parsed items 融合与 RRF/加权策略属后续实测增强。
- 后续公开混合检索只能通过显式模式或新端点启用；TRD 给出响应契约与跨层调用方覆盖，不改变旧调用方默认值。
- 原始记录的时间/app 过滤沿用现状；派生知识按仍有效的来源过滤，同一支持来源需满足全部过滤条件。无来源时间/app 的记忆在对应过滤下不参与；回答所用声明须有满足过滤的支持来源，不把知识发布时间当作工作发生时间。
- 诊断分别表示 disabled、no_hits、timeout、failed、ok；部分来源失败可用其余结果并标记 partial，全部启用来源失败返回 unavailable，与成功搜索零命中严格区分。
- 检索与回答提交前复核知识状态、输入修订与删除记录；同一原始来源的 OCR、语义、记忆派生副本不作为多个独立事实累计支持度。缓存需随相关修订、发布、废止、删除及 provider 配置变化失效。
- 不包含云搜索腿，沿用 §13.4 裁剪结果。办公连接先将明确范围内的内容导入本地；普通问答不临时调用办公平台搜索，断网时仅使用仍有效的本地证据并显示抓取时间。

验收标准：

- **AC-R3-01**：旧 `/search` 的默认、升序、多页、过滤和零命中契约回归通过；未启用后续增强时无向量/外部 provider 依赖。
- **AC-R3-02**：多应用/跨日期知识过滤、版本切换、来源删除与缓存命中均返回符合条件的当前数据。
- **AC-R3-03**：固定语料与查询下分别演示部分失败、全部失败、禁用和真实零命中；后续融合须对人工相关性标注评测，不能只用输出快照证明质量。

### R4 本地记忆归属与 MemoryProvider 演进

- 首版本地 memories 是本系统写入真源，现有 REST `/memories*`、MCP `update-memory` 和显式文件出口继续可用；本轮不引入远程双写，删除按 R6 补齐受管副本清理。
- 后续 Provider 化独立于功能增强验证：`LocalSqliteProvider` 包装现有行为；接口声明 search/write/delete/过滤等能力，不能要求只读 provider 假装支持写入与删除。
- 首次外接仅做只读检索，Mem0 为验证候选，Graphiti 暂不实现；结果包含 provider 标识、稳定条目 id/修订与可核验引用。缺少稳定身份或可查看来源时不作为持久知识证据。
- 外部条目不自动写成本地事实或回写任何记忆服务；问答引用所需内容可以按 R6 已声明的模型出口发送。关闭 provider 后停止请求，并清除本系统缓存的正文/嵌入与含其内容的派生副本。已有外部条目删除只控制本地缓存与后续召回抑制，不声称远端原件已删除。
- 连接配置保存 endpoint、enabled、能力与凭据引用；API Key 仅存 Keychain，不进入设置正文、日志或导出。查询文本也是外发数据，连接启用前展示其范围（R6）。
- 跨设备同步代码已删除，旧表字段保留（§13.3）；跨设备一致性、远程写入和远程删除保证必须另立需求，不由本期接口隐含承诺。

验收标准：

- **AC-R4-01（首版）**：本地 CRUD、MCP 与文件出口契约回归通过；未配置时无外部记忆请求，受管文件删除与失败重试可验证。
- **AC-R4-02（后续）**：纯 Provider 重构单独通过现有测试；只读接入的来源、超时、过滤、关闭清理和本地删除后不再召回均通过，再启用外部 provider。

### R5 带引用问答（/answer）

- 首版新增 `/answer`，同时提供 MCP 工具：检索 → 有界证据包 → 用户 AI Preset 普通 completion → 声明与引用检查 → 回答。返回 answer_id、结论、逐项引用（稳定来源或知识 id/版本）、不确定项、检索诊断、needs_confirmation；不用 agent 执行循环。
- 每项事实性结论必须有对应支持来源，不能只在末尾附一组真实但无关的引用。原始来源、归档原文节选、用户记忆和模型推断分别标注；来源不明或 AI 自动生成且未确认的 memory 标为未核验，不能冒充用户确认事实。confidence 仅辅助展示，不单独决定可回答性。
- 没有足够证据时返回“证据不足”；证据冲突时展示冲突与待核实项，不擅自选边；全部检索源失败时报告“检索不可用”。缺证、冲突或高风险条件未确认时 `needs_confirmation=true`，不能靠用户点确认就补出缺失事实；高风险建议仅列有依据的内容，不执行操作。
- 采集文本、外部记忆与历史 AI 输出均视为待分析数据，不可执行其中指令；模型生成内容不得绕过审核反向成为已确认事实。证据包限制来源和长度，不加载任意来源要求的工具或网络地址。
- 显示或保存回答前复核来源与版本有效性，期间被删除/失效的内容不得发布；已经保存的回答与缓存纳入 R6 管理。可点开原文/知识版本；只有媒体已清理时显示“文本可查、媒体已清理”，不冒充仍可播放。

验收标准：

- **AC-R5-01**：在 §8 冻结语料上逐项核对结论与引用；真实但不支持结论的引用、伪造引用均判失败。
- **AC-R5-02**：无证据、冲突、过期知识、归档引用、全部检索失败及采集内容中的提示注入分别得到规定行为；同时检查可回答问题的回答率。
- **AC-R5-03**：问答生成中删除来源或替换知识版本，返回结果不得泄漏旧正文；REST 与 MCP 使用同一规则。

### R6 数据生命周期与隐私

- **用户主动删除优先于任何版本保留或 retention 豁免**。删除确认前展示影响范围；接受请求后立即禁止受影响来源及其派生内容用于新检索/问答，旧任务不得重新提交。记录删除进度，受管副本未清完时显示“清理中/待重试”，不能显示完成。
- 首版采用保守传播：受影响的 Work Unit 修订、知识版本、activity history 叙事、保存的回答等派生正文整份清除，不只删关联或引用。多个来源支持的对象也遵守此规则；独立未受影响来源可重新生成候选，但不得自动复发旧版本。历史只保留不含正文/节选的删除标记与版本关系。
- 统一覆盖 frame、ui_event、audio、memory 和飞书/腾讯会议导入来源；传播包含原文节选、FTS、以后新增的向量、请求/结果缓存、持久任务的输入/输出和本系统管理的文件副本。通过依赖关系追踪多层派生，而非只依靠 frame 外键。
- 自动保留清理与用户删除按下表区分；共享来源只有在最后一个需保留的当前发布版本解除引用后才解除豁免。暂停待复核的当前发布版本仍保留文本证据，废止/替代版本不单独获得豁免。

| 触发 | 原始记录与媒体 | 派生内容与问答资格 |
|---|---|---|
| 用户主动删除 | 删除范围内记录与受管副本；不受发布状态保护 | 所有受影响派生正文清除，历史仅保留删除标记；禁止重放复活 |
| retention 清理当前发布知识的来源 | 保留被引用的 frame 文本、音频转写或 UI 事件必要文本及身份；视频、音频媒体、截图文件不豁免 | 原文仍可核验；媒体失效单独展示，不影响文本引用 |
| retention 清理未被当前发布知识保护的来源 | 按现有策略清理记录/媒体 | 保留编译时固化的必要原文节选与出处，标记“已归档引用”；不把模型摘要当原文。候选发布前仍需足够可核验来源，否则补证后再审 |
| 知识废止/替代 | 解除该版本独占的保留豁免，仍被其他当前版本引用的来源继续保留 | 历史可查但不参与普通问答；用户主动删除仍清除历史正文 |

- 受管 Agent 注入文件只清理本系统拥有的区块/sidecar，保留用户正文；目标不可写时持久记录重试。人工导出、用户自行复制的文件/备份以及外部 provider 原件不属于可撤回副本，明确列出范围；不把本地删除等同于第三方删除。办公导入来源及后续外部条目本地删除保留不含正文的身份抑制记录，防止同一条目重新导入/召回；不得删除平台原件。断开连接停止读取并暂停对应来源参与问答，已导入副本可选择保留或清理，默认保留但停用；清理进入同一删除链。
- 本系统管理的迁库回退、任务恢复和恢复导入必须应用现存删除记录，再开放读取；旧 store、队列或索引重建不得复活内容。首版“清除”指应用层正文与受管文件不可再读，不承诺 SQLite 空闲页、介质或用户离线旧备份的取证级擦除。
- 原始采集库不上传。外部模型可能收到查询、所需 OCR/转写节选、记忆和知识上下文；后续远程 embeddings 也属于模型出口。后续只读 memory provider 只接收用户启用的查询/过滤，不接收本地记忆写入；模型/provider 已接收的数据无法由本地删除撤回。
- 现有显式本地文件同步是独立出口：展示目标路径、写入类别、是否可能被其他 Agent/同步软件继续读取，以及可清理范围。知识不自动写入文件（§13.5）。设置页统一展示模型/provider/文件出口，办公数据入口及其账号、范围、保留/清理在「连接」页展示；诊断只保留标识/计数/耗时，不记录密钥或完整证据正文。
- 既有 Pi 执行会话与通用 MCP 是显式出口：记录客户端/适配器身份、本地传输方式、传送的回答/来源节选，或后台任务所需证据包。客户端可能再调用其配置的模型并保存会话；可识别的端点应展示，无法读取其配置时明确标记由客户端管理，不宣称无外发。第三方客户端已经接收的回答无法由本地删除撤回；本系统创建并管理的执行会话、目录和结果纳入清理，不能因使用 Pi 或国内模型而跳过该要求。后续新增 Runtime 同样遵守，不在首版引入 R10 具名联调。

验收标准：

- **AC-R6-01**：分别删除 frame/audio/ui_event/memory/办公导入来源，验证原文、摘要、知识历史、回答、缓存、受管文件与索引无受影响正文命中；文件失败时状态为待重试，恢复后完成。
- **AC-R6-02**：验证模型执行、发布、索引重建、应用重启与迁库回退同时遇到删除时，不复活内容；多来源/多版本依赖按上述保守规则处理。
- **AC-R6-03**：retention 下三类采集来源的发布文本豁免、媒体清理、归档引用和共享豁免释放符合矩阵。
- **AC-R6-04**：设置与连接清单涵盖模型上下文、办公入口请求、后续 embedding/provider 查询、现有文件及 Runtime/MCP 出口；未启用出口无对应请求/写入，配置/日志不含密钥。

### R7 反馈与知识修订

- 首版回答提供“无关/有误/已过时/缺少步骤”反馈，关联 answer_id、查询、具体声明、知识版本与来源修订；没有定位到版本时先进入待处理列表，不自动停用所有检索结果。
- 用户确认某版本有误后立即暂停该版本普通问答，显示待复核原因；处理动作是修订候选、废止或确认仍正确并恢复，均记录理由与处理结果。
- 用户编辑/纠错不自动改变 prompt、模型参数或其他知识；跨条目推广后置。反馈引用的已删正文按 R6 清除，仅保留处理状态等无正文记录。

验收标准：

- **AC-R7-01**：演示“回答有误→定位 v1→暂停→编辑 v2→自审发布→再次提问只使用 v2”；历史反馈可追溯且不会把错误版本重新召回。
- **AC-R7-02**：无法定位版本的反馈进入待处理；驳回/恢复均可记录原因，删除来源后反馈界面不残留其正文。

### R8 后台运行与恢复

- 首版随桌面应用运行；关窗口但应用仍在后台时继续执行，退出应用后暂停，不承诺仅运行 CLI 引擎就能沉淀。启动时恢复未完成任务，界面显示暂停原因、待处理数与最老积压时间。
- 用轻量持久任务记录管理 pending/running/succeeded/failed/paused/cancelled，记录输入修订、尝试次数与进度；不要求引入外部队列。成功提交与进度推进保持一致，崩溃后重试不得重复产物，失败窗口不得被进度跳过。
- 沿用串行优先级“交互查询 > 新区间抽取 > 历史补处理/编译”；批量任务在有界步骤间让出执行。交互排队达到 10 秒即结束本次请求并返回可重试的忙碌状态，用户也可提前取消；普通问答 SLA 包含排队时间，忙碌响应计为失败。
- 模型离线、应用暂停或达到已启用的每日调用/费用预算时停止新调用，保存积压；恢复后按优先级限量补处理，不一次性占满机器。首轮验收按用户授权不启用费用或每日调用硬上限，仍统计调用量；单次证据包/上下文上限、串行调度和资源限制继续生效。每次调用有超时，网络重试一次、非法输出回修一次，单任务总调用最多三次；永久失败待人工重试，用户可暂停或取消任务。
- 默认从首次启用的增量边界处理新增就绪区间；历史回填由用户单独启动，首轮默认范围为启动回填时向前 7 天内仍有有效来源的数据，后续可调整范围。显示范围、待处理量与进度；暂停/取消和重启恢复不得重复编译，也不得把“未选择回填”的旧数据当作新增积压或自动扩展到全部历史。TRD 明确跨启用边界区间与迟到证据归属，禁止重复/漏处理。
- 首轮验收模型固定为本机 Pi 的 provider `shawnhub-copy`、model `deepseek-v4-flash-0731`（§9），记录 Pi 版本与参数；模型调用复用现有 AI Preset/Pi 路径，不能把全局 Pi 已配置误写成 screenpipe 内已打通。凭据仅使用 Keychain 引用，失败不静默换模型。
- 删除/源修订使旧任务取消或过期，结果提交必须检查当前来源有效性。具体单次超时、证据包上限与批次大小由 TRD 根据指定模型和机器的小样本结果确定；可选每日预算应支持未设上限状态，不能以跳过失败窗口满足 SLA。`/answer` 继续遵守 R5 普通 completion 边界。

验收标准：

- **AC-R8-01**：关窗后台、退出重启、休眠唤醒、断网/恢复、非法输出与已配置预算超限均有正确状态；未配置每日预算时不因虚构费用上限暂停，任务不丢失、不重复、不无限重试。
- **AC-R8-02**：长批任务期间交互不会无限排队；取消或删除后不提交旧结果，进度与产物一致。
- **AC-R8-03**：首次启用的增量边界、跨界区间、迟到来源和 7 天回填范围可核验；回填可暂停/取消/恢复，范围外旧数据不触发模型调用，既有历史仍可查看。

### R9 飞书与腾讯会议只读接入

- 首版仅 **飞书、腾讯会议**。飞书读取授权的消息、文档正文和元数据；腾讯会议读取已有权限的会议信息、云端转写及智能纪要。WPS 不实现、不列入首版验收。复用官方 CLI 等成熟能力，技术取舍见 TRD；不要求再次完成规划前 PoC。
- 所有接入操作统一放主侧栏 **「连接」**：发现依赖、连接/重新授权、查看账号和能力、选择资源与时间范围、立即同步、选择是否自动同步、暂停/恢复、重试、断开，以及清理已导入资料。详细依赖/版本信息折叠展示，不要求用户拼命令或把密钥粘贴到聊天。
- 授权与读取范围独立：账号可读不等于全部导入。首次连接不自动抓取历史；用户保存范围并确认同步后才读取。默认手动，自动同步需显式启用；只能在已选范围内推进。首版每个平台一个账号，账号变化创建新的来源命名空间，避免跨账号混淆。
- 只读取必要内容，不发消息、不修改文档/会议、不授予共享权限、不下载完整历史录像。API Key 及新增持久凭据按 Keychain 边界管理；已有 CLI 登录只引用，不复制凭据、不因应用断开而注销用户全局 CLI。消息/会议权限不足、云录制未开启、转写处理中、依赖缺失、版本不支持均如实展示。
- 来源含平台/账号/对象身份、版本、发生时间、读取时间、读取方式、内容完整度和回链。未知发送者/说话人保持未知，智能纪要标为平台 AI 生成内容，不当作原始转写。部分分页、截断、正文提取失败不能展示为完整成功。
- Screenpipe 继续记录实际活动并补足本地可见内容/音频；接口内容可补齐明确关联的工作证据，不能以“导入过资料”证明用户执行过某流程。同一资源的截图、转写和 API 副本关联去重，保留独立观察时间；无需为两款工具先做专用 AX parser 才能接入。
- 导入、修订、断开、权限变化与本地删除共用 R1/R3/R6 的来源有效性、知识失效、索引清理和重导入抑制。缩小读取范围立即停用范围外来源；清理与保留选项明确，不调用远端删除。不扩展全量同步或通用办公操作框架。

验收标准（在实施阶段执行，本轮不运行）：

- **AC-R9-01**：分别冻结飞书与腾讯会议的 CLI/客户端版本、账号能力和已选资源样本；各自预先标注的关键内容单元 ≥90% 正确导入且可被中文查询检索，失败项计入分母，身份/时间/来源归属逐项正确。飞书覆盖消息和文档；腾讯会议以真实转写及时间回链验收，截图不能替代转写。未录制/无权限时不能宣称转写可用。
- **AC-R9-02**：依赖缺失、权限失效、限流、转写处理中、分页未完与离线均有正确状态；部分内容保留完整度标记，未知身份不猜测。适配器拒绝写操作和范围外读取，取消/断开后旧任务不能提交。
- **AC-R9-03**：两款工具纳入原有 ≥10 会话验收集，至少一条跨工具流程完成 Work Unit→SOP→问答→来源删除；同对象重复导入、修订和重新连接不造成重复或删除复活。资料可访问与用户实际活动有明确区分，指标沿用 §8。
- **AC-R9-04**：从「连接」完成连接/授权、范围选择、手动同步、自动同步开关、暂停/重试和断开/清理；状态在离开页面与应用重启后保持一致。首次授权不自动全量导入，不暴露密钥；旧连接功能保持可用。

## 6. 非功能需求

- **热路径零回归**：新增任务为离线批处理，通过既有 SQLite 写入协调入口持久化，不新增独立写入连接绕过协调；不得破坏 <20% CPU / <3GB RAM 的 release 目标。固定机器/采集负载分别测量关闭与开启 Local Brain 的 CPU、RAM、写等待和磁盘增长，不能只凭“离线”判定无影响。
- **沉淀 SLA**：机器唤醒、桌面应用运行、引擎和指定模型可用、未暂停且未触发已配置预算期间，就绪 Work Unit 在 15 分钟内完成（可配置）；暂停时间单独统计，积压不隐去。固定模型与语料的普通问答 ≥80% 在 60 秒内完成，包含检索/排队/校验；失败与拒答分别统计，不把失败当快速成功。首轮不设每日调用/费用硬上限，模型与执行参数按 §9 冻结。
- **文案与 prompt 中文优先**：延续 c9456cb25 的约定，用户可见文本与生成 prompt 使用简体中文。
- **平台**：macOS 先行验证；实现遵守仓库跨平台抽象，不引入平台私有依赖。
- **兼容声明**：办公工具按“产品＋接入方式＋CLI/客户端版本＋账号能力＋操作系统＋已验证能力”声明支持；升级后先重跑对应样本，不把某一版本通过外推到其他工具、模块或版本。通用 MCP 记录协议测试版本；具名国内 Runtime 声明随 R10 后置。
- **可观测**：抽取成功率与事实支持率、失败/暂停原因、队列积压、各路命中与耗时、拒答/可回答率、知识待审量与审核耗时、复核到期量、删除失败项和后续 provider 失败率。区分确定性检查结果与人工质量评价。

## 8. 验收与成功指标

本节是首版验收真源，R1–R9 与本节的 AC 编号用于技术设计与验证追踪；其中 AC-R4-02 已明确为后续增强，R10 整项后置。以下为本轮采用的产品验收阈值，尚无达标实测；TRD 固定评测样本、机器、Pi/Preset/model、办公客户端及通用 MCP 协议测试版本与命令，禁止看到结果后更换分母。

- **AC-EVAL-01 语料**：≥10 个真实开发相关工作会话，覆盖需求分析、调研和业务沟通，其中 ≥3 个来自同一重复流程；自动区间可由用户在评测时标成会话，不要求首版新增手动会话功能。冻结 30–50 条人工标注的保留验收查询，含 ≥10 条可回答问题、无证据/冲突/版本过期各 ≥5 条，另覆盖错误引用与提示注入。调试查询另选，不使用保留验收答案调 prompt/排序；记录预期来源和应拒答原因。
- **AC-EVAL-02 抽取/编译**：在上述会话上人工核对所有用于知识编译的事实性字段，≥90% 有证据支持；错误或未知不能计为事实。产出 ≥1 份用户确认可用的 SOP，识别 ≥1 个现有笔记未覆盖的流程变体；发布版本全部事实性步骤/条件/分支有支持来源。
- **AC-EVAL-03 问答**：保留验收集每个结论的引用可核验，无支持依据的事实性结论为 0；人工判定可回答问题中 ≥80% 得到有实质内容的正确回答，避免全拒答通过。至少一条异常处理问题同时返回当前发布知识与原始证据。该“0”仅指冻结验收集，不宣称开放世界零幻觉。
- **AC-EVAL-04 生命周期**：R1–R9 中属于首版的重复、修订、删除、retention、恢复与兼容场景全部通过；至少完成一次真实 SOP 的 v1→纠错→v2→来源删除，确认受管旧回答和索引正确失效，通用 MCP 新工具调用符合当前状态。向量启用后同样验删除，不以首版没有向量免除后续检查。
- **AC-EVAL-05 审核负担与持续使用**：固定验收模型为 `shawnhub-copy / deepseek-v4-flash-0731`，记录实际 Pi/Preset 路径、每份草稿审核耗时、每日集中审核总时长、待审积压、调用量及 §6 资源/SLA；按每日约 5 分钟审核设计，观察期间与积压统计口径在测量前冻结，由本人确认负担可接受且愿意持续使用。首轮费用和每日调用总量不作否决阈值；若审核负担过高，先调整候选质量/数量，不靠全部抑制候选或引入更多召回路数通过，仍须达到 AC-EVAL-02/03。
- **AC-EVAL-06 出口**：对所有已启用模型、既有 Pi 受管会话、文件和通用 MCP 出口做可观测验证，未超出 R6 声明；后续加入 embeddings/provider/新 Runtime 时增补对应验证再启用。
- **AC-EVAL-07 国内办公接入**：冻结飞书和腾讯会议的接入版本/账号能力/场景清单；原有 ≥10 会话与保留查询集覆盖两款工具及至少一条跨工具流程，分别满足 AC-R9-01，腾讯会议包含真实转写与时间回链，并完成「连接」操作链。通用 MCP 新调用核验回答、修订和删除，不要求国内 Runtime 消费联调或执行能力评估，不把已安装当成兼容测试结果。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模型抽取错误或流程混合 | 格式合法但知识有误 | 字段级证据、未知留空、适用条件分组；按 §8 人工核验，不盲目扩大时间窗 |
| ledger 重建与旧任务写回 | 来源悬空或删除后复活 | 稳定身份、输入修订、提交校验与删除记录；R1/R6/R8 联合验证 |
| activity history 迁移回归 | 叙事丢失或回退恢复已删内容 | 单写入方、快照对比、可重入迁移；回退先应用删除记录 |
| 自动清理与历史保留混淆 | 证据丢失或隐私内容残留 | R6 生命周期矩阵覆盖三类采集来源、记忆及受管副本 |
| 首版召回质量不足 | 找不到已发布知识 | 先做 FTS 基线与人工相关性标注，再按证据决定是否增加向量/融合 |
| 自审积压与知识过期 | 无人维护或错误反复出现 | 驳回去重、到期暂停、逐版本纠错；记录审核耗时与候选积压 |
| 后台任务占用资源 | 影响采集或交互 | 有界步骤、持久进度、预算/暂停与固定负载测量 |
| 办公 CLI/平台变化或权限不足 | 内容缺失、身份/时间误判、连接不可用 | 固定适配版本、严格只读范围、明确失败与部分结果；实施时验收并保留活动采集 |
| 全局 Pi 配置与应用内调用路径不同 | 指定模型在列表可见但应用调用失败，或取消/清理不完整 | TRD 核对现有 AI Preset/Pi 映射、单次调用、取消与受管会话；不静默换模型 |
| 用户决定跳过规划前接入与模型验证 | 实施时可能遇到账号资格、CLI 契约或模型执行差异 | 风险前置到连接/模型实现任务，失败有恢复路径；不改变两款工具目标、不把未测计为通过 |
| 历史回填与自审积压 | 启用即消耗大量资源，草稿超过每天可审量 | 新增优先、历史显式近 7 天试跑、可暂停取消、约 5 分钟集中审核与可见积压 |

## 12. 知识类型演进路径

v1 仅三种 P0 类型（见 R2）。本节约束其后续演进方向与节奏，防止两个方向的失败：过早开放类型定义导致编译质量失控，以及硬编码到无法演进。

### 12.1 v1 设计约束（TRD 必须遵守）

- 三种类型实现为**内部注册表**：每个类型 = `{json schema, prompt 模板, 校验器, 渲染器}` 四件套，pipeline 只依赖注册表，不感知具体类型。后续演进是加条目，不是改管道。

### 12.2 第一次演进：静态配置化

- 注册表外置为配置文件；用 Checklist（SOP 派生）与 Case 作为第一批「配置新增」类型验证机制。
- 硬底线：
  - 类型必须约束在**有限字段词汇表**内（title / steps / conditions / symptoms / escalation 等通用槽位），不允许任意自由字段，否则召回、去重、审核台渲染全部退化为通用文本，知识对象失去相对原始记忆的增量。
  - 类型定义本身版本化，类型 schema/prompt 版本进入知识编译身份；Work Unit 仅随自身抽取 schema/prompt 或输入变化重算，类型有废止路径。

### 12.3 第二次演进：AI 对话创建（起草向导，非自由创建）

- 流程：用户自然语言描述想沉淀什么 → AI 提案类型定义（schema + prompt + 适用场景）→ 用户确认 → 影子模式（只产出候选、不进召回、积累样本人工确认）→ 转正。
- AI 创建的类型**绝不自动发布知识**。
- 实现可复用 pipe 形态先例（pipe.md = prompt + frontmatter 的 AI 任务包）。

### 12.4 可提前独立项

- **对话式修订知识内容**（非类型）：审核台「编辑」支持对话式修订草稿。成本低于类型配置化，针对「草稿不满意但懒得手改」的高频痛点，可作 v1.5 独立评估（§9 第 7 项）。

### 12.5 演进触发信号

满足任一即启动 §12.2 配置化：

1. 第 4、5 个类型需求真实出现（非想象需求）；
2. 出现非流程类知识沉淀需求（某个人、某个项目状态、某类会议模式）；
3. 固定类型运行 3–4 周后，编译候选中稳定出现「内容有价值但塞不进现有类型」的模式。

### 13.1 保留策略与知识证据链（影响 Phase 0 schema，最重要）

- 已核对事实：retention `All` 会清理 frames、audio_transcriptions 与 ui_events，ledger 触发器按三类来源删除 evidence；ledger 重建也会改变 evidence 行身份。
- 原裁决保留“文本证据豁免、媒体不豁免”的方向；2026-09-07 补齐为 R6 的统一矩阵：覆盖三类采集来源，区分原文节选与模型摘要、当前发布与历史版本、自动清理与主动删除。R6 是唯一行为真源。
- 设计约束：retention 以当前发布知识的稳定来源集合做批量豁免，不能只 join 临时 ledger evidence_id 或 frame_id；计量文本/节选增长与共享引用释放，不以文本较小为由省略生命周期管理。

### 13.2 商业档位钳制短路

- 事实：`FREE_ACTIVITY_HISTORY_HOURS=24`、`settings_restrict_activity_history`、`HistoryAccessPolicy` 残留于 activity_summary / streaming 等路由，会把知识编译时间窗人为压到 24 小时并截断 preflight 证据。
- 裁决：local-only 构建下策略短路为无限制；**不物理删除代码**，降低日后合并上游的冲突面。Phase 1 落地。
- 状态（2026-09-07 瘦身记录）：`activity_history_is_restricted` 恒返回 `false`，钳制实际不生效；Phase 1 验证不截断抽取窗口，不附带无必要的残留代码清理。

### 13.3 memories 跨设备同步
